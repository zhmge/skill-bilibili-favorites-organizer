# B站接口的非显然行为

这份文档只记「按直觉做会做错」的地方。常规用法看脚本即可。

## 接口一览

| 路径 | 用途 | 备注 |
|---|---|---|
| `/x/web-interface/nav` | 验凭据、取 mid | `code=0` 且 `isLogin=true` 才算登录态有效 |
| `/x/v3/fav/folder/created/list-all` | 列收藏夹 | `up_mid` 必填 |
| `/x/v3/fav/resource/list` | 列收藏夹内容 | **会静默少给，不可当全集** |
| `/x/v3/fav/resource/ids` | 收藏夹的权威全集 | **终态断言的唯一基准** |
| `/x/v3/fav/resource/move` | 移动条目 | 需 `BILI_JCT` |
| `/x/v3/fav/folder/add` / `folder/del` | 建夹 / 删夹 | 需 `BILI_JCT` |
| `/x/web-interface/view` | 视频详情 | 判「是否失效」靠 `state` 字段 |

## 列表接口会静默少给数据

这是本 skill 存在的最硬的理由。

**实测**：默认收藏夹 `media_count` 声明 456 条，`/resource/list` 用 `order=mtime` 和 `order=view` 两种排序都只返回 446 条 —— 少 10 条，不报错、不提示、分页也正常结束。同一时刻 `/resource/ids` 返回 456 条。

音乐夹少 1 条、篮球夹少 1 条，同理。

**那 10 条是什么**：`bvid` 存在、`aid` 有效，但 `/x/web-interface/view` 返回 `state != 0` —— 对接口而言它们不可见。它们依然实实在在占着收藏夹的位置。

**后果**：如果只用 `list`：
- 按 list 的内容分类，这 10 条永远分不到；
- 验收时用 list 检查「默认夹空了没」，会**显示已空**，而实际上还躺着 10 条 —— 静默失败。

**做法**：
- 元数据（标题 / UP / 时长 / 播放 / 封面 / 简介）从 `list` 取；
- 条目集合从 `ids` 取；
- 差集里的条目单独用 `view` 补元数据；补不到就如实标成「接口不可见」，**不要猜、不要跳过**；
- 验收断言一律基于 `ids`。

## 风控：HTTP 412

**实测**：请求最小间隔 0.5 秒必然触发 `HTTP Error 412: Precondition Failed`。改成 1.1 秒后稳定。

- `MIN_INTERVAL = 1.1`，加上 0~0.15 秒随机抖动。
- HTTP 层风控码：`412 / 403 / 429`。命中后退避 `20 × (attempt+1)` 秒再试，累计仍失败 → 熔断。
- 业务层熔断码：`-352 / -412 / -799`（抛 `CircuitBreak`，调用方立即停止）。
- 鉴权失效码：`-101 / -111`（抛 `AuthError`）。
- **`-101` / `-403` 也可能是瞬时抖动**，不必然是凭据过期。先隔一会儿重试，别急着让用户重新登录。

撞上风控时的正确反应是**等 30 分钟以上再跑同一条命令** —— 脚本本身支持续跑，不需要另写恢复逻辑。

## 封面：Referer 防盗链

B站图片 CDN 按 Referer 判断是否放行：

| Referer | 结果 |
|---|---|
| 不带 | 200 |
| `https://www.bilibili.com` | 200 |
| `https://workbuddy.cn`（资料库页面发出的） | **403** |

所以 **B站封面直链不能写进资料库页面** —— 页面里必然 403。必须先把图下载到本地，再以字节上传到资料库图床，拿到托管直链。

**缩略图变体**：在封面地址后拼接 `@320w_200h_1c.webp`，同一张图从 551,699 B 降到 8,804 B（约 1/63）。批量 600 张的差别是分钟级 vs 秒级。

## 默认收藏夹的识别

**`attr` 恰好等于 1 的才是默认收藏夹。**

★ 不要用 `attr & 1`。实测（2026-10-07，9 个夹）：

| 夹 | attr | 二进制 |
|---|---|---|
| 默认收藏夹 | **1** | `1` |
| 摄影 / 篮球 | 3 | `11` |
| 健身康复 / AI / 游戏开发 / 音乐 | 22 | `10110` |
| 数学 / 计算机 | 23 | `10111` |

`3`（`11`）和 `23`（`10111`）的第 0 位同样是 1 —— 用位与会把 4 个普通夹误判成默认夹。
这次侥幸没出事，只因为接口把真默认夹排在了列表第一位。**判定写成 `attr == 1`。**

`collect.py` 另有一层兜底：`attr==1` 找不到时按标题 `默认收藏夹` 找一次；
命中多个候选会打警告，取第一个 —— 无论哪条路，都要在输出里看见那句确认。

不要只按标题字符串匹配 —— 用户可能改过夹名，所以标题只作兜底、不作主判据。

## move 的语义

`/x/v3/fav/resource/move` 等价于「从源夹移除 + 加入目标夹」。

- **它不会清理视频原有的其他归属**。一条视频同时属于「游戏开发」和「AI」时，把它从默认夹移到「杂项」，它仍留在原来那两个夹里。所以「去重」是一个需要人决定的独立问题，工具不自动处理。
- 单次能带几条**没有官方说明**，首次使用必须小批试跑（`apply_moves.py --probe`）。
- 传参是 `resources`，格式 `aid:type` 逗号分隔（`type` 通常为 2）。

## 网络：必须绕开本机代理

脚本一律用 `urllib.request.ProxyHandler({})` 强制直连。

原因：本机环境变量里配了 `HTTP_PROXY` / `HTTPS_PROXY`，走代理时对 `api.bilibili.com` 的探测结果不可靠（曾把未监听的本地端口误判成 502）。直连实测 78ms，出口是本机 ISP，也更接近真实浏览行为。

## 判定只读标题和简介

不要为了给一条视频分类去调 `view` 接口或读字幕。理由：

- 成本：600 条逐个调接口 = 十几分钟 + 风控风险；
- 收益：标题 + 简介对绝大多数视频已足够判断主题；
- 副作用：拖长流程会让人失去耐心，从而放松后面的人工门禁。

判不出来的，标 `low` 交给人 —— 这比多花十分钟猜一个可能错的结论更有价值。
