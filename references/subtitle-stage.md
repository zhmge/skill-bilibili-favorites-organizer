# 阶段 6 · 字幕：判定、兜底、写回

只在「本次新落入 计算机 / 游戏开发 / AI」的视频上做。存量不重算，否则每轮都要重跑几小时 GPU。

## 三条约定，优先级最高

| # | 约定 | 边界 |
|---|---|---|
| 1 | **多分P 大合集只做前 5 集** | 第 6 集及以后**一律不做**，也不记为「失败」——单列「按约定未提取」。单分P、合集单集不受此限 |
| 2 | **单分P > 20 分钟跳过 ASR** | 与 #1 叠加使用 |
| 3 | **`page` 语义随形态变** | `multi` = 视频自己的分P序号（URL 要带 `?p=N`）；`season` = **合集内第几集**（目标 bvid 已锁定那一集，URL **不能**带 `?p`，带了会报「分P 不存在」）；`single` 恒为 1 |

约定 #1 是 2026-10-07 用户后加的。**已按全量跑过的那批按用户意见保留、不回溯**，但之后不许再 `--all`。

## 判定顺序

1. **先自检登录态**，用一条「库里已知有原生字幕」的对照视频证明 cookie 生效。
   不过就**不发任何请求**退出 —— 匿名访问字幕列表接口恒返回空数组，会把「没登录」伪装成「本来就没有」。
2. 抓原生字幕（`bilibili-subtitle-fetch`）。
3. 判定「确实没有原生字幕」的，按体量决定是否本地 ASR 兜底（`video-audio-to-srt`）。

**要证明「某接口匿名不可用」，必须拿一条已知有数据的样本去测。** 否则「空结果」无法区分
「没登录」与「本来就没有」—— 这是本项目里反复用到的方法。同样地，判定「这分P 真没字幕」
需要双端点各测多次都为空，而不是测一次没拿到就算数。

## 写回口径（写之前必须先定，改口径比改数据贵）

`字幕状态` 的语义是 **「有没有字幕」**，不是 **「覆盖了百分之多少」**：

| 值 | 含义 |
|---|---|
| `有字幕` | 至少 1 个分P 有**原生**字幕 |
| `ASR生成` | 无原生、但至少 1 个分P 有 ASR 字幕 |
| `无字幕` | 0 覆盖（已查证无原生字幕，且 ASR 或未跑、或判无人声、或按规则跳过） |
| `待定` | **还没查**，不是「查了但没查全」 |
| `视频失效` | 视频已删 |

**覆盖率不许塞进状态。** 有一个具体后果：清单页的「有字幕」筛选器 = `字幕状态 ∈ {有字幕, ASR生成}`，
把「已按规则做干净、只是没覆盖全部前 5 集」的视频标成 `待定`，它会被筛选器排除、
还永远挂一个黄色告警，而且因为规则上无解，这个告警永远不会消。

覆盖率交给三个字段表达：

| 字段 | 口径 |
|---|---|
| `收录分P` | text，`已解决/该视频分P总数` —— **分母是总数，不是应取数** |
| `已解决分P` | number，范围内 `B站字幕数 + ASR字幕数` |
| `应取分P` | number，本轮约定范围：多分P = `min(n, 5)`；单P / 合集单集 = 1 |

于是「有字幕 收录 2/58 分P 应取 5」这种写法同时表达了「拿到了」和「只拿到这些」，
不需要靠状态去承担。

## 四种「没拿到」必须分开记

分P 粒度的待定清单（单独一张表）里，`未获取原因` 要能一眼分辨：

| 原因 | 判定依据 |
|---|---|
| 无人声 | ASR 跑通但产出 **0 段** —— VAD 判无语音 |
| 超 20 分钟跳过 | 该分P 时长 > 阈值，且无原生字幕 |
| 整集超阈值跳过 | 合集条目的目标是**整段课程**，远超阈值（见下方坑 1） |
| 取音失败 | `playurl` 未返回音频流 |
| 按约定未提取 | 大合集超前 5 集 |

**「无人声」和「没拿到字幕」不是一回事，前者是视频的客观属性、无法补救，
后者是流程缺口、下轮可续。** 混在一起会让「按约定未提取」的几十条淹没掉真正可补的几条。

## 坑

### 1 合集条目的「目标」是整段视频，不是某个分P

`season` 形态下，`plan` 里的 `p` 是**合集内第几集**，而 `duration` 是**该 bvid 自己全部分P 的时长和**。

实测：`BV11Ee36bEiL` 是 44 分P / 31474s（8.7 小时）的课程，`BV1cwhd6MERn` 是 74 分P / 41579s（11.5 小时）。
它们的 `pages[0].duration` 是 242s / 1188s —— 那是**首个分P**的时长。
判「是否超 20 分钟」时必须用整集时长，用单个分P 的时长会得出完全相反的结论
（第一版就是这么写错的，把两条本该跳过的误判成该跑）。

### 2 解析 `.srt` 别按「至少 3 行」切块

`build_srt.py` 产出的 SRT 有两个特征会让朴素解析器静默丢数据：

- **首块是来源链接**（`https://www.bilibili.com/video/BV…/`），不是 cue；
- 存在**只有序号 + 时间行、文本为空**的 cue。

正确写法：按「≥2 行且其中一行匹配时间行」判定，并且**保留头部块**。
按「≥3 行」判会把空文本 cue 丢掉 —— 实测把 530 段读成 528 段，且不报任何错。

### 3 连续超短同文段是解码幻觉，不是口癖

静音期 whisper 会按帧吐 token。实测 `BV1N34y1H7x7_P4` 的 idx 145–164 是
**20 段连续 `呃`、每段 0.02–0.14 s**（合计 3.74 s），`BV1JCUfYbEGq_P24` 的 273–276 是 4 段 `好`。

两条判据，满足其一就删：

- **幻觉串**：连续的 ≥4 段文本完全相同且长度 ≤2 字 → 整串删除；
- **回声**：连续的 ≥2 段文本相同，且**第 2 段起**每段都 < 0.15 s → 保留第 1 段，删其余。

`.15 s` 这个门槛是安全的：真实音节不可能短于它，所以不会误删。
**时长达标的口癖要保留**（`对不对`×2、`点击浏览`×2 都留着），删的只是「短到不可能是语音」的那些。

直接用 `scripts/clean_degenerate_srt.py`（先不带 `--write` 预演）：

```bash
<python> scripts/clean_degenerate_srt.py <字幕目录> [--write]
```

它同时处理了下面坑 2 的两个解析陷阱，所以不要另写一个「自己按行切」的版本。

### 4 VAD 产出 0 段是**正确结果**，不是失败

不能因为「跑完了、rc=0」就把它记成「已解决」，那会把「没语音」谎报成「有字幕」。

反过来，也要排除「VAD 误杀」。做法是**关掉 VAD 再转一遍做对照**：
如果出现的是「作词作曲 李宗盛」「中文字幕——YK」这类训练集套话（`no_speech_prob` 0.53–0.71），
那就是非语音幻觉，0 段是对的；如果出现连贯、有信息量的句子，才是误杀。

还要顺手验一下**取音没错位**：音频时长应与分P 时长一致（实测差 < 1 s）。

### 5 写临时探针脚本时不要 `transcribe(路径)`

本机 `av` 与 faster-whisper 的 `av.open(..., metadata_errors=…)` 签名不兼容，
直接传文件路径会抛 `TypeError`。用 `wave` + numpy 读成 16k 单声道 float32 数组再喂 `transcribe()`。

另外 **ctranslate2 找 cublas DLL 只搜 `PATH`**，`os.add_dll_directory()` 对它无效 ——
探针脚本里要显式把 `site-packages/nvidia/*/bin` 追加进 `os.environ["PATH"]`，
否则会报 `Library cublas64_12.dll is not found`。
（本项目已经踩过两次：一次是主转写脚本、一次是后台探针；**后台探针那次还因此挂死 43 分钟**，
最后是被当成「仍在运行的任务」发现的。跑长任务时如果它超过预期时长还没动静，去查进程，别干等。）

### 6 `asr_rc=0` 不等于有内容

判「已解决」要同时看 **rc=0** 和 **`segments.json` 里段数 > 0**。只看 rc 会把上面坑 4 的情况算进去。

### 7 写库形状

`batch_add` 与 `batch_update` 的 `records` 元素形态不同，见 `data-model.md`
「写库的调用姿势」一节 —— 套错一层会报 `records[0] 校验后为空，无有效字段`。
